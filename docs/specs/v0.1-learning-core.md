## 2. 技术与访问选择

- Next.js App Router、React、TypeScript；CSS变量与定制样式实现深色工作台+暖白纸卡。lucide图标；Markdown安全渲染。
- Supabase客户端仅服务端使用，沿用连接指南的URL/secret环境变量名称；全部新表默认拒绝anon/authenticated直接读写。
- 使用本项目独立 `apm_users`、高熵访问码哈希和HMAC httpOnly cookie，不接触旧 `system_users` 或 `sb-session`。会话签名密钥独立生成，不复用数据库key。
- 本地开发提供“本机学习者”入口，仅 development + loopback host + 显式开关启用；服务绑定127.0.0.1。生产必须使用访问码，不自动登录。
- 课程和源文保持私有。所有API校验服务端会话，写请求校验同源；服务端取得user_id后调用新RPC，禁止客户端指定写入其他人。
- 数据库若暂不能执行DDL，继续完成代码、可审阅迁移和本地验证，但不能将本地模拟状态称为远端已上线。需要补齐DDL权限后完成远端环节。

## 3. 数据合同

表前缀固定 `apm_`：migrations、users、settings、chapters、lessons、source_revisions、cards、card_revisions、review_states、review_events、study_activity。

单一私有知识库简化掉首轮未用到的多课程/成员表，章节和卡片均通过稳定UUID识别；后续共享通过新增course与成员关系演进。卡片唯一主章节/学习单元，concept_keys用于去重与兄弟卡识别。

- source_revisions保留原文哈希、相对路径、标题、Markdown；脚本排除.obsidian/.claudian。
- cards固定身份；card_revisions不可变内容；source_refs关联真实source_revision与行号。
- review_states以(user_id,card_id)唯一，保存完整FSRS JSON与due、version等索引字段。
- review_events追加保存rating、before/after、配置版本、卡修订、幂等键和撤销关系。
- settings带version和预算/时区/路线/熟悉度。参数变更不批量重写due。
- 评分RPC和撤销RPC只授权service_role，在事务中锁定状态、检查版本、写事件和状态。

API基线：`/api/auth`、`/api/bootstrap`、`/api/study`、`/api/reviews`、`/api/reviews/undo`、`/api/settings`、`/api/lessons/[id]`、`/api/health`。可合并查询端点，但不得省略所有权、版本和错误契约。

## 4. 评分与队列

- Completely forgot/Hard/Good/Easy对应1/2/3/4；中文完全记不清/模糊记得/记得/很熟练。Hard必须是独立答对，答案后眼熟算Again。
- FSRS库预览四种结果，签名token绑定用户、卡片、内容/状态/配置版本、预览时间与候选状态。服务端验签，禁止任意state_after。
- 重复client_event_id返回同一结果；相同幂等键不同内容报409。服务端签名token有效期10分钟。
- 到期优先，新卡受当日已学数与设置上限约束。预算不足暂停新卡；同日重学和阅读也算投入时间。
- 兄弟卡当天错开但不改due。用户主动选择单卡加练时允许明确的额外练习，不偷偷计入计划完成。
- 撤销仅允许该卡最新有效评分；已发生后续事件则409。
- 刷新、路由切换后从真实记录重建进度。无网络不推进云端完成计数。
