# SPEC-003 · 零延迟客户端交互与分层预取缓存架构

状态：已实现并验证（2026-10-17）。对应用户对全站模块切换与课程阅读“两阶段延迟（跳页前 1~2 秒 + 进页后从 Supabase 拉取再等 1~2 秒）”的归因分析与全面架构升级要求。

## 1. 现象与根因归因分析（Root-Cause Attribution）

用户感知到的“整体交互非常不跟手，响应非常延迟”由**四个串行或放大的架构瓶颈**共同造成：

### 瓶颈一：点击跳转前的 1~2 秒卡死（Next.js App Router 隐式 RSC 服务端往返 + 主线程同步重计算）
1. **App Router `<Link>` 与被补丁的 `window.history.pushState` 触发 RSC Flight 请求**：
   - 虽然 `Studio` 已挂载在 `src/app/layout.tsx`，且 `src/app/[[...slug]]/page.tsx` 返回 `null`，但页面内使用 `next/link` 或直接调用被 Next.js 16 猴子补丁（monkey-patch）的 `window.history.pushState` 时，Next.js 会在动态 catch-all 路由 `/[[...slug]]` 下派发 `ACTION_RESTORE`，强制等待服务端返回 RSC Flight payload 后才提交 `usePathname` 更新。当服务端或连接稍有波动时，点击后 URL 与界面在 0.5~1.5 秒内毫无反应。
2. **渲染期无缓存的 $O(N \times M)$ 同步重计算阻塞主线程**：
   - 全库已从早期 59 张卡扩充至 **408 张卡、875 个修订、70 篇课程、最多 1,000 条复习事件**。
   - `WorkspaceSidebar`、`KnowledgeAtlas`、`Today`、`Cards`、`Progress` 在每次渲染时直接同步执行 `studySummary(data)`、`orderedLessons(data)`（70 篇排序）、`searchLessons(data)`，并在数组内反复 `.find()` 线性扫描 408 张卡片与状态。

### 瓶颈二：进入文章页后的 1~2 秒二次等待（零缓存 + 零预取 + 鉴权与正文串行查库）
1. **文章正文与卡片详情完全无客户端缓存与预取**：
   - `LessonReader` 每次挂载都把 `body` 置空、显示“正在打开课程原文…”，再发起 `/api/lessons/[id]`。即便刚读过的课程或相邻上下课，每次点击都必须重新跨公网去 Mumbai (`ap-south-1`) 的 Supabase 拉取。
   - 目录树、课程列表、上下课翻页在鼠标悬停/聚焦或阅读当前课时，没有任何预取（Prefetch）。
2. **API 每次请求先串行查 `apm_users` 表验证会话**：
   - `src/app/api/[...path]/route.ts` 中的 `user(req)` 在 HMAC 签名校验通过后，每次请求都**先串行执行一次** `db().from('apm_users').select('id,display_name').eq('id',session.userId).eq('active',true).single()`（耗时 ~400–600ms），拿到结果后才开始查 `apm_source_revisions` 或 `cardDetail`（再耗时 ~400–600ms）。
   - 单次打开课程或揭示答案被迫承受 **2 次串行跨洋数据库 RTT（合计 1~2 秒）**。

### 瓶颈三：Bootstrap 全表线性匹配与重复建连开销
1. **`apm_card_revisions` 内存 $O(N \times M)$ 线性查找**：
   - `src/lib/repository.ts` 的 `bootstrap()` 拉取全库 875 条修订后，用 `cr.data?.find(...)` 为 408 张活动卡逐一线性查找匹配（$408 \times 875 \approx 357,000$ 次比较）。
2. **每次调用 `db()` 重复实例化 Supabase Client**：
   - `src/lib/db.ts` 每次调用都新建 `createClient` 实例，未复用单例客户端。

## 2. 升级目标与验收标准（Acceptance Criteria）

| ID | 维度 | 架构升级内容与验收判据 | 状态 |
| --- | --- | --- | --- |
| **AC-P1** | **0ms 瞬时客户端路由（Instant Location Store & Native History）** | 在 `Studio` 客户端壳内采用基于原生 `History.prototype.pushState` / `replaceState` + `useSyncExternalStore`（`useInstantLocation` / `instantNavigate`）的 `InstantLink` 组件，绕开 Next.js 16 对 `window.history.pushState` 触发 `ACTION_RESTORE` RSC Flight 的拦截，并在 `onMouseEnter` / `onFocus` / `onPointerDown` 预热。点击顶部模块、左侧目录、面包屑、上下课、卡片练习时，**同一帧（0ms）立即切换视图**，彻底消除等待服务端 RSC 往返的 1~2 秒卡顿。 | 已通过 |
| **AC-P2** | **课程与卡片客户端内存缓存 + 智能预取（Client Cache & Prefetch）** | 建立统一的客户端资源缓存层（`src/lib/client-cache.ts`）：<br>1. **缓存命中 0ms 渲染**：已加载过的课程 Markdown（按 `lessonId`）与卡片详情（按 `cardId`）在内存中持久保留，再次点击或返回时**0ms 立即渲染正文**，不出现“正在打开课程原文…”闪烁。<br>2. **多级智能预取**：鼠标悬停（`onMouseEnter`）/聚焦（`onFocus`）目录项、课程行、上下课链接、答案出处时立即触发预取；打开某节课程后自动预取“上一课 / 下一课”原文；Bootstrap 后自动预取“下一篇未读课程”原文。 | 已通过 |
| **AC-P3** | **消减 API 串行数据库 RTT（Parallel Auth & Data Query）** | 1. 服务端先同步校验 HMAC Cookie 提取 `uid`，再通过 `Promise.all` 将 `userById(uid)` 与 `lessonSource` / `cardDetail` / `reviewContext` **并行执行**，将 `/api/lessons/[id]`、`/api/cards/[id]`、`/api/study/reveal` 的数据库往返从 **2 次串行 RTT 压缩为 1 次并行 RTT**。<br>2. 复用配置感知的单例 Supabase 客户端（`src/lib/db.ts`）。 | 已通过 |
| **AC-P4** | **即时答案揭示与 FSRS 预览预取（Pre-fetched Reveal）** | 在 `Study` 学习页加载当前题卡时，后台即刻预取该卡的 `study/reveal`（含 `CardDetail` 与签名 `Preview` token，绑定状态版本与设置版本并在变更或过期时自动失效）。当用户按下 `Space` 或点击“显示答案”时，若预取已就绪则 **0ms 立即展开答案与四档评分按钮**。 | 已通过 |
| **AC-P5** | **派生数据索引化与 Memoization（O(1) Lookup & Memoized Summary）** | 1. 在 `studySummary` / `selectNext` / `searchLessons` / `bootstrap` 中使用 `Map` / `Set` 替代 $O(N^2)$ 的 `.find()` 嵌套循环。<br>2. 在 `WorkspaceSidebar`、`KnowledgeAtlas`、`Today`、`Cards`、`LessonReader`、`Progress` 中使用 `useMemo` 缓存派生状态，并使用 `extractMarkdownHeadings` 缓存课程目录标题解析结果。 | 已通过 |
| **AC-P6** | **Bootstrap SWR 快照水合** | 支持客户端 `sessionStorage` 快照水合（Stale-While-Revalidate）：刷新页面时若有同会话快照可立即呈现界面骨架与内容，同时后台拉取最新 `bootstrap` 无感校准；登出或 401 时立即清除。 | 已通过 |

## 3. 代码落盘清单

- `src/lib/client-cache.ts`：客户端内存缓存、in-flight 并发请求去重、课程/卡片/Reveal 预取、Markdown 标题缓存解析、`sessionStorage` Bootstrap SWR 快照、左键点击判定。
- `src/components/workspace-navigation.tsx`：`InstantLink` 浅路由链接组件、侧栏目录树与面包屑悬停/聚焦预取、派生列表 `useMemo` 优化。
- `src/components/knowledge-atlas.tsx`：知识地图章节与课程行接入 `InstantLink` 与悬停预取、`Map`/`Set` O(1) 统计。
- `src/components/studio.tsx`：接入 SWR 快照、下一未读课自动预取、`LessonReader` 缓存直读与相邻课程自动预取、`Study` 答案与预览自动预取、`CardDialog` 缓存直读。
- `src/app/api/[...path]/route.ts`：同步提取 `sessionUserId`，并行执行 `userById(uid)` 与业务查询。
- `src/lib/repository.ts`：`bootstrap` 修订组装 `Map` 化，新增 `lessonSource`。
- `src/lib/db.ts`：Supabase 客户端单例缓存。
- `src/lib/learning.ts` & `src/lib/navigation.ts`：`Map`/`Set` O(1) 查找优化。
- `tests/performance-contract.test.ts`：覆盖上述全部架构契约与缓存行为的单元与静态契约测试（共 31 项测试全部通过）。
