# 制卡与入库规范

状态：2026-09-06 已实现正式批次发布链；14 张初始样卡及第1、2章45张审校卡已入库。

## 1. 目标与成功标准

目标不是把 70 篇材料改写成问答全集，而是帮助学习者独立回忆 AI PM 做判断所需的概念、机制、边界与方法。以大章节为课程边界，以单个可评分的知识点为卡片边界。

- 每张卡有一个明确问题、一段最小答案、可检查的必答点和可追溯来源。
- 每张卡在 30–90 秒内可以作答；复合问题拆卡，长背景放入课程。
- 答案必须被对应来源支持；补充推断要注明，不能悄悄当成原文事实。
- 学习者能根据答案判断四档评分，评分后产生真实到期时间。
- 制卡完成、审校通过、上传成功、浏览器可学习是四个不同状态，分别留证。

## 2. 内容组织与优先级

课程沿用知识库的 9 个大章、70 篇材料。每张卡归属一个主课程，可以引用其他课程的来源；同一概念通过 concept_keys 关联，避免重复堆卡。

| 章节 | 核心卡规划目标 | 制卡原则 |
| --- | ---: | --- |
| 第1章 | 20 | 角色、问题定义、基本判断 |
| 第2章 | 25 | AI PM 能力地图与交付边界 |
| 第3章 技术攻克 | 180 | 模型、Prompt、RAG、Agent、Evals 的机制与权衡 |
| 第4章 | 15 | 原型、开发协作、验证方法 |
| 第5章 | 55 | 产品方案、交互、成本与验收 |
| 第6章 | 30 | 应用案例、故障诊断、迁移判断 |
| 第7章 | 20 | 商业模式、价值与单位经济 |
| 第8章 | 0 | 行业观点主要作为阅读；稳定结论经核实再制卡 |
| 第9章 | 15 | 精选产品思考题，不机械转写全部 440 题 |
| 合计 | 360 | 上限式规划，不作为已完成卡量或强制凑数指标 |

已按用户当前优先级完成第1、2章预算。后续建议先审校已有14张，再生产第3章 RAG / Agent / Evals → 第3章其他基础 → 第5章产品设计 → 其余章节。没有卡片的课程显示“卡片待制”。

建议按 10–20 张组成一个批次。一次只做一篇或一组相邻材料，完整通过审校与入库检查，再扩大批量。

## 3. 从原文到卡片的工作流

1. **冻结来源**：记录相对路径、全文 SHA-256、标题、段落/行范围与导入时间。复用 apm_source_revisions 的不可变来源快照。
2. **提取知识点**：先列出“概念 / 因果机制 / 决策条件 / 易错边界 / 实践步骤”，删除重复、口号和无证据结论。
3. **确定学习动作**：每个点只选一种主动作：解释、区分、诊断、决策或应用。避免“你是否了解”这类不能评分的问题。
4. **起草卡片**：先写必答点，再反推正面问题；答案要求和题目难度必须匹配。
5. **事实审校**：逐条对照原文，核实数字、条件、术语。价格、模型榜单、版本、供应商能力等时效性内容默认不做长期记忆卡；确需保留时加日期与当前官方来源。
6. **教学审校**：检查单一目标、答题耗时、是否泄露答案、评分能否一致、是否和已有卡重复。可以交给次一级模型独立审校；主 Agent 对争议和高风险事实定稿。
7. **发布审校**：只有 accepted 批次可以上传。批次文档记录接纳/修改/拒绝原因，不能让生成模型自己宣布全部合格。
8. **入库与抽验**：先校验文件，再上传、回读、查看卡片；在独立测试用户上执行评分与撤销，禁止污染正式学习记录。

### 卡片类型

| 类型 | 正面结构 | 答案结构 |
| --- | --- | --- |
| 概念 | X 是什么、解决什么问题？ | 定义 + 关键边界 |
| 对比 | 在条件 Y 下，A 与 B 的差别是什么？ | 2–3 个决定性维度 |
| 机制 | 为什么 X 会导致 Y？ | 简短因果链 |
| 场景判断 | 给定目标和约束，优先检查/选择什么？ | 选择 + 理由 + 改变选择的条件 |
| 故障诊断 | 出现现象 X，如何定位？ | 最小排查顺序 + 可观察证据 |

“列出全部 Agent 架构及优劣”应拆成多张。避免只记缩写、无上下文的数字，以及答案可以任意发挥却要求精确评分的问题。

## 4. 字段契约与版本

现有表映射：

- apm_chapters：大章，位置和目标卡数。
- apm_lessons：课程，稳定 source_key 与所属章节。
- apm_source_revisions：原文快照，hash 与正文；来源改变创建新快照。
- apm_cards：稳定卡片身份、主课程、概念键、顺序、生命周期、active_revision。
- apm_card_revisions：题目与答案的版本、必答点、误区、来源引用、预估耗时。
- apm_review_states / apm_review_events：个人记忆与事件，不属于内容发布范围，禁止批量制卡脚本覆盖。

新批次采用独立 JSON 源文件：

```json
{
  "batch_id": "ch03-rag-001",
  "status": "draft",
  "cards": [{
    "canonical_key": "ch03.rag.retrieval-boundary.001",
    "lesson_source_key": "与课程清单一致的相对路径",
    "concept_keys": ["rag.retrieval-boundary"],
    "revision": 1,
    "title": "简短知识点标题",
    "kind": "场景判断",
    "prompt": "一个可独立评分的问题",
    "answer_short": "最小充分答案",
    "required_points": ["可检查的要点一", "可检查的要点二"],
    "pitfalls": "最常见误区及边界",
    "estimated_seconds": 60,
    "source_refs": [{
      "relative_path": "来源相对路径",
      "content_hash": "来源全文 SHA-256",
      "line_start": 1,
      "line_end": 10
    }],
    "review": {"status": "draft", "reviewer": "", "notes": []}
  }]
}
```

当前数据库 source_refs 是 JSON，可容纳行范围，但当前 UI 仅跳转课程，尚不定位历史版本与行号。批次交给 `content:*` 命令，不要传给旧 seed 脚本。

命名稳定，不根据题目文字重新计算身份。现有 C01–C14 身份保留。文字修订应新建 revision，再切换 active_revision；不能原地覆盖已被复习事件引用的版本。若学习目标实质变化，新建卡片并退役旧卡。来源/答案修订不自动清空用户进度。

## 5. 当前已可复现的入库方法

在项目目录执行：

```sh
npm ci
npm run content:prepare
npm run db:inspect
npm run db:seed
npm run db:verify
```

连接来自本机 `.env.local`，需要 NEXT_PUBLIC_SUPABASE_URL、SUPABASE_SECRET_KEY、APM_OWNER_ID、APM_OWNER_ACCESS_CODE；KB_SOURCE_PATH 指向知识库。不得把真实值写入文档。

- content:prepare 当前专用于 9 章 / 70 篇 / 14 张试点：读取知识库原文，以及 `docs/plans/2026-09-05-curriculum-and-cards.md` 中 C01–C14；使用 homeCodes 显式绑定课程；输出被忽略的 `data/private/seed.json` 与清单。
- db:inspect 只读检查表/RPC 元数据。
- db:seed 每批 20 条，按用户 → 章节 → 课程 → 来源 → 卡片 → 卡片版本依赖顺序上传；设置只在缺失时建立，来源与卡片版本使用 ignoreDuplicates。
- db:verify 检查数量、匿名权限隔离、RPC 幂等、冲突与撤销；创建独立临时用户并清理自建数据。
- 数据库首次建表使用已提交 SQL migration，通过 Supabase SQL Editor 执行；service key 不能替代管理 API 进行任意 DDL。此项目迁移已经执行，不需要为了重跑 seed 再建表。

**当前限制**：现有 prepare 有固定 14 张断言和课程映射，seed 也不是新版本发布器。修改同一 revision 后重跑会跳过旧版本，并不会更新答案。禁止用该方式批量扩至 360 张或发布修订。

## 6. 已实现的正式发布工具

所有命令通过 npm 传参时使用 `-- --batch <file>`：

1. `content:validate`：校验 schema、来源 hash/行范围、课程/章节一致、canonical_key 唯一、必答点和本地 seed 映射。
2. `content:diff`：核对远端课程、来源修订、卡片身份和版本，列出新增、修订或 unchanged；不存在隐式删除。
3. `content:publish`：只接收 accepted，通过 service-role-only RPC 在单个事务中新增卡片与修订、切换活动版本并记录批次账本。
4. `content:verify`：按稳定主键回读内容、必答点、来源引用、active_revision 和账本 hash。

实现依据为 `docs/specs/content-batch-publishing.md` 与 `supabase/migrations/202609060001_content_batches.sql`。批次 ID + hash 提供幂等；同 ID 异内容拒绝。回退通过新修订切换或退役卡片完成，保留历史事件与修订。

## 7. 验收清单

每批必须留存：来源清单、卡片草稿、独立审校结果、dry-run 差异、发布回执、回读结果、抽样学习证据。小批次内容全部审校；浏览器抽验至少覆盖一种概念卡、一种场景卡与一个来源链接。

拒收条件：无出处、来源不支持结论、题目包含多个独立目标、答案只写“视情况而定”、来源版本漂移、同义重复、声称生成数量却未入库、未验证就把状态标记为 published。
